# 導入と受入確認

## 導入前の状態

利用者から、Mattermost 12.0.1へのインストールと既読人数・名前一覧の基本表示が動作したとの報告を受けています。スレッドや画面外判定、実際の複数アカウントによる一連の動作、実デスクトップアプリの受入確認は継続中です。新たに導入する環境では、まず限定チャネルで確認してください。

開発側からサーバーへの接続や設定変更は行っていません。インストールと実機の画面確認は利用者が実施しました。

## 利用者への説明

導入時に次の内容を共有してください。法的な適否を保証する文書ではありません。必要な社内確認は別途行ってください。

> 業務連絡の表示状況を確認する目的で、Web・デスクトップ版で投稿が前面に連続1秒表示されたことを記録します。メンバーには既読人数、投稿者本人には表示済みの人の名前とユーザー名を表示します。閲覧時刻は本プラグインの記録項目に含めません。記録は投稿作成から30日を対象とします。スマートフォンアプリでの閲覧は含みません。既読は読了・理解を示さず、即時返信の要求や勤務評価には使用しません。

個人情報保護委員会の [従業者の個人情報の利用目的 Q2-2](https://www.ppc.go.jp/all_faq_index/faq1-q2-2/) と [従業者モニタリング Q5-7](https://www.ppc.go.jp/all_faq_index/faq1-q5-7/) を参照して、利用目的、実施責任者、対象、ルール、保存期間を整理してください。後者は安全管理措置としてのモニタリングについての説明で、本プラグインを直接評価したものではありません。

## アップロードと設定

1. `dist/SHA256SUMS` と配布ファイルが一致することを確認します。macOSでは `shasum -a 256 ファイル名`、Linuxでは `sha256sum ファイル名` で確認できます。
2. Mattermostのシステムコンソールでプラグイン管理を開き、`com.nito.viewport-read-receipts-0.1.2.tar.gz` をアップロードします。
3. サーバー側で独自プラグインのアップロードや未署名プラグインが許可されていない場合は、そのポリシーを確認します。本手順は署名ポリシーを自動で緩和しません。
4. プラグインを有効化します。この時点では `TrackingEnabled=false` のため記録されません。
5. プラグイン設定の `ChannelIDs` に検証用チャネルIDを設定します。最初から空欄の全チャネル対象にはせず、限定した確認を推奨します。
6. 利用者への説明後、`TrackingEnabled=true` にします。初期値は連続1000ms、投稿から30日です。
7. ブラウザ／デスクトップを再読み込みします。

対象チャネルIDはチャネル情報等で取得してください。DM・グループDMを限定対象にする場合も、その会話のチャネルIDが必要です。

## 実機の受入確認

基本表示の報告は受けていますが、以下の全項目が完了したという扱いにはしていません。

投稿者Aと閲覧者Bの別アカウント・別ブラウザプロファイルで確認します。同一アカウントを2画面で開くだけでは権限制御の確認になりません。投稿者本人は人数に含まず、同じ閲覧者を複数タブで表示しても1人と数えます。画面外判定の確認には、Bがまだ表示していない新規投稿を使ってください。一度付いた既読は画面外へ移動しても取り消しません。

| 確認項目 | 合格条件 |
|---|---|
| ロード | システムコンソールでプラグインエラーなし。Webの開発者コンソールにも起動エラーなし |
| 通常チャネル | Bが投稿を前面に1秒以上表示するとAの「既読」が増える |
| 画面外 | Bがチャネルを開いただけで、画面外の対象投稿は増えない |
| スクロール通過 | 1秒未満で通過しても増えず、戻って連続表示すると増える |
| バックグラウンド | 別タブ・別アプリを前面にしている間は増えない。戻ってから改めて計測する |
| 親投稿と返信 | 親だけ表示しても画面外の返信は増えない |
| 右側スレッド | 各返信を表示した場合、その返信だけが増える |
| スレッド画面 | 「スレッド」画面で親・返信の記録と一覧が正しく動く |
| 重複表示 | 同じ投稿を通常表示とスレッドで表示してもBを二重に数えない |
| 非公開チャネル | 参加者だけが記録・人数取得できる |
| DM／グループDM | 通常と同じ条件で相手を記録する |
| 投稿者限定の一覧 | Aにはボタンと名前一覧。Bには人数のみ。管理者でも投稿者でなければ一覧不可 |
| API権限 | BのセッションでAの投稿のreaders APIを直接呼ぶと403。非参加者のcounts／seenは投稿ごとに403 |
| 退会・無効化 | 脱退・無効化したユーザーを一覧・人数に出さない |
| スマートフォンアプリ | アプリで閲覧しても、このプラグインの記録は増えない |
| 添付のみ | 添付領域を表示した場合に増える。添付を開いた証明ではないことも確認 |
| 長文・折り畳み | バッジがフッターに見える。本文の表示条件を満たした場合だけ増える |
| ダイアログ・検索 | 覆われた本文や検索結果だけの表示では記録しない |
| 保存データ | ユーザーID配列・保存対象日数以外に閲覧時刻・本文・IPを保存していない |
| サーバー再起動 | 記録が保持され、プラグインが復帰する |
| 負荷 | 対象人数・投稿数で操作遅延とAPI負荷を確認。性能の実測値はまだない |
| デスクトップ | 実際に使用するOS・Mattermostデスクトップ版で通常表示と各スレッドを確認 |

自動テストは独立した検証画面と偽のAPI、サーバーのAPI代替実装を用いています。この表の実機受入確認を代替するものではありません。

## 停止・戻し方

- `TrackingEnabled=false` で新規記録と人数・一覧のAPIを停止できます。すでに画面に表示された人数は再読み込み／次回設定取得まで残ることがあります。
- さらにプラグイン管理でプラグインを無効化し、クライアントを再読み込みします。本体の投稿・リアクション・標準の未読情報は変更していません。
- 無効化だけでは保存済みのKV記録を即時消去しません。期限切れ・投稿削除時の処理と、Mattermostのバックアップ保持方針は別です。
- アンインストールによるKV消去動作は実機未確認です。データ完全消去が必要な場合は、Mattermostの運用担当者が対象プラグインのKVとバックアップを確認して実施してください。直接DB削除のコマンドは本手順に含めません。
