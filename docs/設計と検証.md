## 構造

- `webapp/src/visibility.ts`: 表示領域・フォーカス・遮蔽・連続表示時間の判定。知らない表示コンテナでは記録しない。
- `webapp/src/runtime.ts`: 投稿ごとの検知、重複排除、最大50投稿ずつの通信、5秒間隔の人数更新、30秒間隔の設定更新、終了時の解放。
- `webapp/src/ui.tsx`: 投稿フッターと、投稿者限定の名前一覧。名前やユーザー名をHTML文字列として挿入しない。キーボード操作・閉じた後のフォーカス復帰に対応。
- `server/plugin.go`: 認証されたセッションとユーザーの照合、現在のチャネル参加・read_channel権限確認、一覧の投稿者制限、KV保存とTTL。

本文下の登録APIを使用し、フッター表示は `.post__body-reactions-acks` 内へポータルで配置します。長文の「もっと見る」の内側だけにバッジが隠れないためです。標準の投稿レンダラーは置き換えません。

### API

すべてログインセッションが必要で、応答は `Cache-Control: no-store` です。

| パス | 用途 |
|---|---|
| GET /api/v1/config | 有効状態・表示時間・対象期間・対象チャネル |
| POST /api/v1/seen | post_ids（最大50件）を表示済みとして申告。記録者はサーバーが認証セッションから決める |
| POST /api/v1/counts | 現在の参加者について人数を取得。名前を返さない |
| GET /api/v1/readers/{post_id} | 投稿者本人に名前・ユーザー名を返す。時刻と未読者名を返さない |

Webクライアントは本体と同じくMMCSRF CookieをX-CSRF-Tokenとして送信します。SiteURLのサブパスにも対応します。POSTにはさらに独自要求ヘッダーを必須とし、クロスオリジンの許可ヘッダーは返しません。任意のuser_idなど未知フィールドは拒否し、本文は8KBまで、投稿IDの形式も検証します。クライアント自身による表示申告のため、監査証明や不正防止の用途には使えません。

### 保存

キーは `receipt_{post_id}`、値は次の形式だけです。

```json
{"user_ids":["表示条件を満たしたユーザーID"],"retention_days":30}
```

AtomicなKVSetWithOptionsで競合を再試行し、並列表示による上書き欠落を防ぎます。TTLは投稿作成時刻を起点に計算し、保存時点の正確な閲覧時刻は値に含めません。保存対象日数は初回の設定と以後の短い方を使用し、既存レコードの期限を延長しません。

## 自動検証と限界

- Go: 実際のHTTPハンドラーをAPI代替実装で実行。認証・投稿者制限・非参加者拒否・無効化・モバイル拒否・TTL・重複・並列CAS・投稿削除・入力検証を確認。
- Chrome／Playwright: 実際のWebバンドルを独立した検証画面に読み込み、スクロール・スレッド・ダイアログ・連続表示・一覧の操作などを確認。API応答は偽の応答です。
- バックグラウンドのテストではPlaywright標準の強制フォーカスをCDPで解除し、別タブに切り替えて `document.hasFocus()` が偽になることを確認します。visibilityState=hiddenの分岐は別テストで状態を模擬します。
- 実ユーザー間の通信、Mattermostのプラグイン起動、実デスクトップアプリ、実DBのTTL消去、再起動復旧、負荷は未検証です。
- 保存期間の30日は今回の実装上の初期値です。法定期間やMattermostの規定値ではありません。
